# 桌宠主题制作参考

版本：1.15（按角色与实际效果调整）；2026-10-27。适用于后续新主题及相关修改。

本文提供默认做法、当前接入约定和验收参考。制作顺序、图集排布、姿态数量、局部编辑方式及布局可根据角色特点和实际播放效果调整；优先复用已有实现，简短记录必要的调整及验证结果即可。已有主题不必为了符合默认做法而重做，也不必为每个角色不断补充特例。资源与坐标有效性、动作映射、输入同步及取消释放等影响程序正确性的要求仍需满足。

用户入口只需一句，例如“生成一套 DeepSeek 娘（蓝色大肥鱼）桌宠主题”。制作时读取本文并结合实际情况完成生成、接入和验证；用户不需要编写动作清单或技术提示词。具名角色或梗图没有用户提供的参考时，先上网核对形象并选择匹配的参考，不自行改造成同题材的原创吉祥物。“不用本地参考”只限制本地旧图，不禁止联网找参考；只有明确要求纯文字原创时才从文字设计新角色。

## 1. 先定角色，再扩展动作

- 先核对角色身份，再做动作：现有角色使用用户提供或网上核实的参考，原创角色使用本轮生成并检查过的基准。保留脸型、头身比、发型、服装、配色和角色气质；梗图还须保留标志性的表情与夸张比例，不擅自美化成普通萌系角色。基准中的静态姿势不锁死，动作和表情变化须保持辨识度。
- 选择符合角色、能与操作姿势自然衔接的移动方式，如飞碟推进、骑扫帚、轻微悬浮或摆尾。默认小幅姿态变化；不为强调“正在移动”强行大幅俯身、横躺或改变轮廓。轻微悬浮可以成立，但须看实际播放中的起停和过渡，不能仅凭静态图平移就判定自然。需要补全造型时先做好基准图。
- 默认采用“少量完整关键姿态 + 局部动作变体”：先制作必要的待机、移动、待按基准；按下从待按基准局部制作。首轮将这四帧放在实际桌宠大小下播放接近与操作，角色辨识度、移动合理性和动作衔接通过后，再补齐其余必需帧。
- 默认将同一主题合并为一张 `atlas.webp`，基础 7 姿态按下表排成 **4 列 × 2 行**，便于制作和维护；需要独立过渡姿态时可增加格位，排布以实际 metadata 为准。生成时可按有效分辨率分批制作，每批参考已确认的角色基准，最后校准尺度和身体锚点，避免独立生成造成跨帧不一致。
- 生图提示词只保留角色参考、画风、动作关系和必要构图约束；帧号、像素坐标、切帧、镜像和测试要求由装配与验收处理，不整篇复制到提示词。局部返修只描述当前缺陷，避免不断叠加角度、百分比和禁止项。

## 2. 素材制作建议

- 同一主题画风、视角和主体比例一致；切帧不能换脸、无故变大变小、换手、多手或改变载具体量。动作需要的前倾、转身和表情变化应保留，不能把“一致”理解为所有姿态不动。
- 同一姿势内的小动作优先从同一基准帧局部替换，例如眨眼与表情改眼睛、眉毛或嘴，按下与松开改操作部位。采用局部替换时，只取动作区域，其余像素保留基准帧。大幅转身、俯身、透视变化或角色风格需要整体变化时，可制作完整姿态，以实际播放中的一致性和自然度判断。
- 遮罩覆盖动作前后的完整范围及必要接缝。手臂、尾巴移开后，先去除旧部件并补好露出的身体或衣服，再叠加新部件，避免残影、双手、破洞和接缝；不得为保留生成漂移而把遮罩扩大到无关区域。局部变体保持裁切、身体锚点和缩放一致，触点随实际动作重新标注。
- 采用“仅局部变化”方案时，装配后检查遮罩外颜色与透明度差异为零；遮罩内核对连接、遮挡和透明边缘。整体姿态变化按预期动作检查，再以正常速度和慢速播放确认没有意外闪动。提示词中的“其他地方不变”不能代替结果检查。
- 有手臂的角色通常用同一只手完成伸手、按下和收回，靠整体接近目标，避免胳膊异常拉长；其他造型可使用适合角色的操作部位或道具。
- 点击可参考“接近目标 → 待按 → 接触 → 松开 → 收回”，按角色特点设计可辨认的反馈。有手部的角色可用指节、指尖和手腕的小幅变化表达轻点；其他角色不必照搬手指动作。以默认尺寸、正常播放速度下能否看懂操作判断效果。
- 中间姿态用于连接待机与操作姿态，按角色的运动方式设计；是否复用、补充姿态或调整姿态差，由实际衔接决定，避免明显跳变或为凑帧数制造动作。
- 待机以稳定、自然为目标。眨眼默认以待机帧为底，仅替换两眼与眼睑局部并检查差异；若表情或风格需要头部等区域联动，可扩大动作范围，核对变化是否有意且连贯。没有适合眨眼的造型可用其他轻微待机反馈，并映射到现有帧号。工作状态不反复播放与实际任务无关的动作。
- 使用真实透明背景，角色和道具完整，边缘干净；不得烘焙背景、文字、目标圈或鼠标。图集留透明间隔，逐帧核对裁切，避免截断和邻帧残留。
- 单图生成可用于完整关键姿态或局部动作素材，保持基准的画风、比例和清晰度；相邻小动作优先局部制作，采用其他方式时也要放回动作序列检查。正式 WebP 图集及 metadata 只保留实际使用的帧，默认无损；基准、局部素材、遮罩和淘汰稿留在实验目录，不随主题分发。打包成图集本身不能修复跨帧不一致。
- 水平镜像会反转发饰等不对称特征，制作前确定是否可接受；不能出现明显反字。不能接受时先解决方案再扩展动作。

## 3. 对齐当前程序

复用现有图片帧、移动轨迹和输入同步机制，不为普通主题增加依赖或动画引擎。以下是飞碟与扫帚采用的 **7 姿态默认排布**，最后一格透明留空；其他排布通过 metadata 描述，当前调用的动作编号必须能解析到有效素材：

| 第 1 列 | 第 2 列 | 第 3 列 | 第 4 列 |
| --- | --- | --- | --- |
| `0` 待机 | `1` 眨眼 | `7` 移动 | `10` 半伸手 |
| `11` 待按／松开 | `12` 按下／拖动保持／指向 | `18` 完成 | 透明留空 |

- 数字是现有程序的帧号，不随格位重编号。缺少独立图片时，逻辑阶段 `9`（减速）复用 `0`、`13`（收手）复用 `10`、`19`（安定）复用 `0`、`22`（返回）复用 `7` 并按移动方向镜像；阶段时长、轨迹和输入回调不因素材精简而改变。
- 有独立姿态的旧主题仍按其 metadata 加载，不强制删图。旧 11 格主题顺序为：`0/1/7/9；10/11/12/13；22/18/19/空`。独立返回帧 `22` 原图朝左；复用的移动帧 `7` 及其他方向性姿态朝右，由渲染器统一方向。
- 默认每格 **768 × 768**、7 姿态整图 **3072 × 1536**（旧 11 格为 3072 × 2304），身体锚点对齐每格宽度的 50%、高度的 70%，帧之间留透明间隔。图内角色也须按相同显示尺度排列，不能只统一格子、保留大小悬殊的原始帧；动作造成的轮廓差异正常，不为填满格子拉伸角色。
- 上述尺寸是默认导出规格，可按素材清晰度和角色比例调整，并同步更新 metadata、验证显示尺度；不要求生成工具一次原生输出整张大图。放大或补透明边不能算增加有效清晰度。
- `rect` 可小于所在格子。已有素材按程序实际显示比例等比缩放，同步换算 `anchor`、`point`、`head` 和头部半径；核对桌面可见大小、身体到触点的距离及镜像结果。原始高分辨率素材保留在实验目录，避免反复重采样。
- 按[动画实现](../src/huanzhizhi/pet/animation.py)和 [metadata](../src/huanzhizhi/assets/themes/metadata.json) 接入，不照搬旧实验的编号和时长。
- 格位齐全不等于动作自然。允许姿态含义相同且衔接自然的帧复用；按实际播放判断起停、操作、返回和完成是否清楚，需要过渡时再补充合适的中间姿态，不为通过“图片必须不同”的检查制造多余动作。
- `rect` 是图集裁切范围；`anchor` 是裁切后局部坐标中的身体稳定点；`point` 是同坐标系中的真实触点。操作帧逐帧标注，不能把身体锚点当触点。
- `anchor.x` 同时作为上方按钮、聊天气泡和状态条的水平布局中心，须标在角色身体中心，不能按头发、尾巴、道具或透明画布的外接框中心代替。布局复用该锚点经裁切、缩放、镜像后的全局坐标；纵向范围参考待机姿态，避免动作切换引起布局抖动。运行状态条使用待机位置的身体锚点，移动操作期间保持在原位，不另加主题专用的水平偏移参数。
- 两侧任务列默认按当前朝向的待机图可见左、右边界等距摆放。道具或特殊轮廓使菜单过远时，可按实际效果采用更紧凑的布局，允许合理覆盖装饰区域；现有扫帚即保留人物附近的紧凑布局。核对左右朝向的可读性、操作便利和遮挡，避免菜单随动作抖动；需要随朝向调整边界时，原地转身也应刷新布局。
- 裁切、缩放、镜像后同步校准坐标与显示比例，最终以宿主实际渲染核对。路径不得越界，裁切必须在图内，坐标须有限，宽高、缩放和半径须有效。
- 待机帧提供 `head` 和 `head_radius_x`，用于现有头部互动；主题大小按现有[可见面积测试](../tests/test_pet_theme_size.py)对齐，并检查人物是否因宽道具显得过小。
- 新主题还需更新桌宠组件和设置中的主题校验、选择项及保存逻辑，保留已有错误处理和切换限制；仅放入图片不会自动出现。

## 4. 验收通过后再交付

- **看实际播放**：与飞碟或扫帚同尺寸播放同一任务，对照待机、接近、点击、拖动、收手、完成和返回。正常速度与慢速都看，确认移动有依据、关键动作可辨、衔接自然；只看拼图或技术测试通过不算制作完成。
- **看操作是否清楚**：在默认尺寸、正常速度下检查左右朝向的单击、双击和拖动，确认角色采用的接触、松开及保持反馈可辨认，再慢放检查过渡。根据实际问题修正相关素材和触点；保留已验证的输入时序，只有复现出时序问题才修改运行逻辑。
- **看实际显示**：检查左右朝向、深浅背景、最小／默认／最大显示尺寸与不同 DPI，核对清晰度、屏幕边缘、气泡和状态条稳定性。模拟检查与实机检查分别记录。
- **看布局和遮挡**：检查左右朝向的待机与动作，上方按钮及状态条按当前身体锚点布局。两侧菜单按选定方案核对间距、遮挡和可操作性；使用紧凑布局时确认装饰覆盖可接受，不只检查中心坐标。再检查转身、拖动和屏幕边缘表现；实机截图与模拟测量分别记录。
- **验证实际交互**：新主题必须进入相关测试；在自建测试窗口检查点击、右击、双击、拖动、提示、连续操作、停止和返回，以及隐藏恢复、主题切换和技能接管。触点与目标对齐，按下、松开与姿势同步，取消后释放输入，提示不额外触发输入。
- **保持轻量**：与飞碟在相同条件下比较待机、首次动作和反复切换的表现；明显卡顿或内存持续增长需查明原因，不为掩盖问题另加刷新或缓存逻辑。
- **按根因修正**：换脸、长胳膊等问题重画相关动作；位置偏移先查标注；顿挫、倒飞先查轨迹和朝向。业务逻辑修改前先复现，不用拉伸、模糊或快速切帧掩盖素材错误。

测试入口与执行方式见[开发说明](development.md)及 `tests/test_pet_*`、`tests/test_foreground_input_native.py`；按改动选择必要检查，确保覆盖新主题。动作质量与功能测试分别记录，关键姿态缺失或动作不成立时继续返修，不以技术测试通过代替视觉验收；测试也不得把“返回必须等于待机镜像”等旧素材缺陷固定为正确行为。

实验资料统一保存在 `artifacts/` 下按主题或任务划分的目录中，包括参考、原始输出、提示词和简短验收结果，不另建根目录 `experiments/`。记录区分通过、失败、未测，交付说明未解决的问题。公开素材补充[来源与分发说明](../licenses/ASSETS.md)。后续发现可复现的新问题再补规则，不预先增加无关流程或未经验证的数值门槛。
