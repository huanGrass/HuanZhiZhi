# 技能开发知识索引

本索引供调查与开发共用；操作范围、目标和交付目录以本轮提示为准。调查阶段只读参考，不执行开发或实机操作。接口细节按下表选读，不要求通读所有文档。

## 工作原则

- 先理解真实调用链，优先复用适用的已有实现和共享组件，再补缺口。底层机制可复用，不代表旧布局、控件和动作适合新需求；保留输入校验、数据保护、暂停、停止与必要错误处理。
- 先验证最简单可行路线：围绕用户目标打通“必要输入 → 核心处理或操作 → 实际结果核对”的最小闭环，再补齐其余明确要求。调查只提出候选路线与关键待验证项，开发才执行验证；复用已有有效证据，不为证明简单而重复搭建原型。
- 复杂度必须有依据：简单路线确实失败或不能满足明确要求时，先定位原因，再增加解决该缺口的最少机制，并在现有记录中简述证据与收益。不把完整历史重建、多路识别、重复校验层或复杂恢复预设为必需；当前状态足以完成任务时优先使用当前状态，只有规则、用户目标或实际验证证明需要历史时才补充历史处理。
- 只实现用户目标，不新增无必要的依赖、包装层或配置。修复前先复现并确认根因；失败先调查，不用简化策略掩盖。简短记录复用依据、能力缺口及证据即可。
- 技能目录只交付代码、清单和必需资源；运行数据统一写入 SDK 的 `session.runtime_dir`，即技能根目录下的 `.runtime/`。截图、日志与诊断放 `runs/`，可清理缓存放 `cache/`，续局等不可随意清理的持久状态放 `state/`；辅助脚本使用 `runtime_directory(技能入口路径)`，不按目录层级推算宿主路径。草稿验证使用自己的 `.runtime/`，最终 output 不携带运行数据；修改技能时宿主保留原有 `.runtime/`，不得用草稿状态覆盖。普通文本日志优先用 `session.emit_log()`。目录接口的具体用法见[接口参考](skill_reference.md#技能内运行数据)。
- 简化不降低安全与完成标准：目标及当前状态确认、输入校验、数据保护、暂停停止、必要超时、结果核对和错误处理随核心链路一起验证；不得为了缩短开发而删除，也不得把最小闭环通过当作全部需求完成。
- 连续输入之间只做必要工作：例如“选中对象 → 点击落点”，同一份足够新、置信度足够且完整覆盖相关状态的观察，可以同时确认选中反馈、目标位置和状态未变；满足下一步条件后及时操作，不为同一状态重复全量识别、多次稳定等待或同步保存调试截图。需要多帧、额外识别或等待时，应有动画、歧义、状态变化等实际依据，不规定所有任务都只识别一帧。动作反馈必须来自该动作之后，优先复用现有时间戳或新帧能力；动作前的缓存不能证明动作已成功，状态变化、暂停恢复或观察失效后须重新确认。
- 保留连续操作的安全边界：每次输入前检查停止请求与目标有效性，反馈不明确时不得继续输入；重试和等待须有界且可响应停止。截图留证优先复用已有画面，放在操作完成或异常边界，避免阻塞相邻输入；必须在操作前完成的数据持久化、数据保护和必要结果核对不能后移或删除，不为移走截图保存而默认新增线程、队列或框架。验证时按需记录相邻输入间的截图、识别、保存和输入耗时，并检查状态变化、模糊反馈、超时及中途停止不会误发后续输入；离线处理耗时与实机输入间隔分别说明。
- 以实际结果验收。离线检查不能代替实机效果，进程正常退出不能代替目标完成。合并相关检查并复用已有证据；连续任务覆盖完整一轮操作及其结果、下一轮及停止，记录启动和单轮耗时，不默认把一轮操作扩大为完整一局游戏或长周期流程。终局等必要边界优先利用真实已有样本或可控复现验证，需要实机证据的部分仍须实测；条件不足时说明缺口并保留草稿，不删除检测或冒充通过。通过后结束，仅因新改动、失败或未解决问题补充验证，不为积累同类证据反复长时间运行。

## 互动体验验收

用于互动方案调查、新建及涉及体验的修改；普通设计细节自行决定，不增加用户审批，用户明确要求优先。

1. **具体承诺。** 用一段完整交互说明用户输入、角色行为、对象响应、结果反馈和恢复操作；给出可观察的通过标准与失败表现。核对素材能否表达动作及其触发、时机和结束条件。角色若承担核心职责，移除后体验不应完全相同；若定位是装饰或陪伴则按该定位判断。
2. **符合场景。** 说明哪些元素常驻及原因，其余按需出现。桌面互动以角色和交互对象为主体，检查实际背景下的遮挡、可读性与视觉层次；透明窗口或通用动画本身不代表体验达标。
3. **先验证核心。** 开发时先在真实宿主打通最小完整交互，查看角色与场景合成后的实际画面。用短录屏或按事件顺序的关键帧检查动作语义、连续性、接触关系及反馈，再补齐其余功能；已有部分复用检查，不重复搭原型。
4. **对照证据。** 在现有开发记录中按“承诺—实际证据—通过或缺口”分别判断功能和体验，主动找未兑现的要求。状态变化、坐标正确或有截图不能代替体验结论，自动操作不等于人工手感认可。缺口修正后再交付；无法满足时说明具体限制和取舍，不冒充完成。
